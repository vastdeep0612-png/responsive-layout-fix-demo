A fixed-width section that scrolls sideways

Problem

On a phone, the page scrolls left and right. The menu stays on one line, and the hero is wider than the screen. This is a standalone copy of a layout mistake that shows up on WordPress and Elementor pages when a section or a widget is given a fixed pixel width.

Cause

The broken hero sets width: 1200px and box-sizing: content-box, so the padding is added on top of 1200px. The menu sets white-space: nowrap, so the links cannot drop to the next line. Nothing in the broken version limits those boxes to the screen.

Fix

The hero uses max-width: 100% and box-sizing: border-box. The menu uses display: flex and flex-wrap: wrap. The text can use the width it is given instead of forcing 1200px.

/* broken */
.hero {
  width: 1200px;
  box-sizing: content-box;
  padding: 24px;
}
nav { white-space: nowrap; }
/* fixed */
.hero {
  width: auto;
  max-width: 100%;
  box-sizing: border-box;
  padding: 24px;
}
nav {
  display: flex;
  flex-wrap: wrap;
}

Before / After

Each frame is 360px wide. The left frame is the broken layout. The right frame is the same content after the fix. The status under each frame is measured in the browser.

Verification

  • Before frame overflows horizontally.
  • After frame does not overflow horizontally.
  • This case-study page itself does not overflow horizontally.
  • The menu in the after frame wraps onto more than one line.
  • The hero copy in the after frame stays inside the frame.
